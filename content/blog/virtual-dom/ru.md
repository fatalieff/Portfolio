Эта статья о причинах появления Virtual DOM и о том, как браузер понимает содержимое.

## Проблема: прямые изменения реального DOM

В эпоху jQuery изменения UI выполнялись напрямую через реальный DOM:

```jsx
document.querySelector('#user').textContent = 'Aisel';
```

Каждая DOM-операция заново запускала render pipeline браузера — вычисление layout, этап paint и композицию на GPU. Одиночные изменения не создавали проблем, но при одновременном обновлении нескольких элементов производительность резко падала.

Тяжесть реального DOM заставила фреймворки вроде React искать альтернативный подход. Так появилась концепция Virtual DOM.

## Что такое Virtual DOM?

При использовании React или Vue UI пишется декларативно — ты не говоришь браузеру, как работать, а просто описываешь, что хочешь увидеть. Фреймворк превращает это описание в лёгкое дерево объектов в памяти (Virtual DOM tree):

```jsx
{
  type: 'div',
  props: { className: 'user', children: 'Aisel' },
  key: null
}
```

Virtual DOM — это не реальный DOM, он не обращается к браузерным API и является лёгкой моделью в памяти. Его главная цель — заранее вычислять изменения.

## Diff и Reconciliation

Когда меняются `setState()` или `props`, компонент перерисовывается и появляется новое дерево Virtual DOM. React сравнивает старое и новое деревья (diff):

1. Если `type` одинаковый, узел сохраняется.
2. Если изменились `props`, применяются только различия.
3. Если отличаются `children`, этот фрагмент рекурсивно diff-ится.
4. Если отличается `key`, старый узел удаляется и создаётся новый.

В результате React выдаёт минимальный список DOM-операций и в commit-фазе применяет их к реальному DOM одним пакетом (batch). Браузер делает reflow/paint только для этих изменений.

## React Fiber

До React 16 процесс diff был синхронным и в больших приложениях приводил к зависанию UI. Fiber делит работу рендера на части, назначает приоритеты и при необходимости может приостановить и возобновить рендер — так UI остаётся отзывчивым.

## Преимущества и ограничения

- **Минимум DOM-операций:** множество мелких изменений сначала вычисляется в JS, затем применяется одним пакетом.
- **Декларативная логика:** разработчик думает только о связи State → UI.
- **Независимость от платформы:** та же концепция работает в React Native и React Three Fiber.

Но у Virtual DOM есть и недостатки: каждый рендер обходит дерево в JS (нагрузка на CPU), современные браузеры сами оптимизируют манипуляции с DOM, а реактивные системы вроде Svelte и SolidJS отслеживают изменения на уровне значений и потому легче.

> **Итог:** Virtual DOM — это имитация реального DOM на уровне JS. Его цель — сократить DOM-операции, группировать обновления и обеспечить декларативную модель UI вместе с производительностью.
